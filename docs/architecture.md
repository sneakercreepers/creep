# Architecture

This is the source of truth for what each part of `creep` does, which way dependencies may point, and which contracts are stable. Decisions that change it go through an ADR ([index](#adr-index)). The package-by-package list is generated in [map.md](map.md) (`make map`), and the trust boundaries, attackers and mitigations are in [threat-model.md](threat-model.md).

## 1. Context

```
            ┌──────────────┐  local repo (untrusted content)
 developer ─┤              │◄──────────────────────────────
 or CI      │  creep (one  │
 (flags,    │  Go binary)  │──HTTPS──► model endpoints (allowlisted, consented)
  config,   │              │──CLI────► docker/podman, local socket only (v0.2)
  policy)   └──────┬───────┘
                   ▼
   reports (SARIF/JSON/MD) · run state (JSONL) · egress.log · payloads/
```

- The scanned repository is **untrusted input**. Its text can only reach the reader and the redacted gateway payload. It can never reach the planner, a shell or config that loosens a gate.
- The only network peers are configured model endpoints. There is no telemetry or update check by default.
- There is no server and no database. Each run is independent; state is files.

## 2. Pipeline

| Step | Component | Input | Output | Version |
|---|---|---|---|---|
| 1 | calibrate | model contract, seeded templates | per-class scores, tier S/M/L | v0.1 |
| 2 | discover | repo files (whole, redacted, to the model) | entry points, sinks and auth as **IDs, enums and line spans** | v0.2 (static analysis in v0.1) |
| 3 | planner | IDs, enums, booleans and bounded numbers; calibration tier | prioritized hypotheses | v0.1 |
| 4 | reader | redacted slices + hypothesis | closed-schema verdicts | v0.1 |
| 5 | sandbox + verify | app build, PoC template | verified / discarded | v0.2 |
| 6 | fix | verified finding | suggested diff | v3 |
| 7 | report | run state | SARIF, JSON, Markdown (HTML v1.0) | v0.1 |

Every model call in steps 1, 2 and 4 goes through the gateway, in this order: `redact.File` → fragment → consent → allowlisted dialer → `egress.log` write-ahead → send. The planner (step 3) is deterministic and makes no model call; a future model-assisted planner would go through the gateway the same way and need prompts in `internal/planner/prompts/` with a token-budget test.

**Step 2 is language-agnostic** ([ADR 0017](adr/0017-language-agnostic-analysis.md), #265). It is an **inventory** of languages, manifests and container files by file name and bytes; a **lexical tripwire** that matches one cross-language table of sink signatures on the redacted bytes; and **model discovery** (`internal/discover`), where the model reads whole redacted source files through the gateway (the same order as above), a few per call with one synthetic canary file, and proposes entry points, sinks and auth as line spans and enums. creep validates each proposal and assigns the IDs. Tripwire hits and proposals are combined by union only, and every candidate gets the worst-case planner flags (input-dependent, not parameterized, not indirect, on a route not authenticated that takes every method). A batch whose reply misses the canary is not believed: its files are `parse_failed` and the run is incomplete. v0.1's `internal/static` (tree-sitter in wazero, Flask, FastAPI and Express) is removed; its language-neutral rules are in `internal/repofile`.

`planner` and `reader` must never import each other. This prompt-injection boundary is the one with the highest stakes in the layering.

## 4. Stable contracts

These follow semver once v1.0 ships. Before then, any change needs a note in the PR and, if the change breaks a contract, an ADR.

One exception is settled so later PRs need not decide it: narrowing what the project file (the scanned repository's `creep.yaml`, the untrusted layer) may set or raise is a security fix, not a contract break. It needs no new ADR; it is recorded in the PR contract note, the `breaking` label when an existing `creep.yaml` stops loading, and the threat model (R4, R5, with the test that pins it), and an ADR whose decision it changes gets an `Amended by` line (as ADR 0013 by #62). Changing which keys or values the operator's layers (user file, `--config`, policy) accept still needs an ADR when it breaks the contract.

| Contract | Where | Versioning |
|---|---|---|
| CLI flags and exit codes | `cli`, `exitcode` | semver |
| Config and policy schema | `config` | No version key: `schema/config.schema.json` (kept in sync by `TestSchemaInSync`) is the contract; a change carries a PR contract note and the `breaking` label in the release notes when an existing file stops loading |
| JSON report | `report` | `schema_version`; schema in `docs/schemas/report-vN.json`; v1 amended additively before the first release (ADR 0009) |
| SARIF | `report` | SARIF 2.1.0 |
| Run state (JSONL) | `state` | per-line `v` |
| `egress.log` line | `gateway` | additive fields only |
| HTTP model contract | `models` | OpenAI-compatible + Anthropic |
| Command model contract | `models`, `gateway` | stdin prompt, stdout JSON; `model.run` split without a shell (ADR 0014) |
| Recipes, presets | `recipes/`, `internal/presets/*.yaml` | own `version:`; data, not code; the preset schema is closed and checked by `TestEmbeddedPresets`. Language kits are not built (ADR 0012 superseded by ADR 0017) |
| Prompts | `prompts/` in the package that sends them: `internal/reader/prompts/` and `internal/discover/prompts/` (one variant per tier S/M/L), `internal/calibrate/prompts/` (one variant, since calibration runs before a tier is known); the reader user turn (`HYPOTHESIS` line, numbered `CODE` lines, truncation notes) is built by `internal/reader/render.go` within `sliceBudget` per tier | `PromptVersion` per package; token-budget test (`prompts_test.go`) |

## 5. Extension points

Contributors add **data**, not core code:

- **Presets** (`internal/presets/*.yaml`, embedded in the binary): command lines for model CLIs, selected with `model: { preset: <name> }`. They are community-owned because they track third-party flags; propose one with the *Model preset* issue form and the manual canary check in [CONTRIBUTING.md](../CONTRIBUTING.md#model-presets).
- **Recipes** (v0.3): source, sink and hint records with fixtures, pinned by commit in `creep.lock`.
- **Inventory and tripwire tables** ([ADR 0017](adr/0017-language-agnostic-analysis.md), #265): a file-name or extension row in `internal/discover/inventory.txt`, or a sink signature with its fixture line in `internal/discover/tripwire.tsv`. Both are embedded data with limits checked by tests (`TestTripwireRowsMatchFixtures`, `TestParseInventoryRejects`); no language needs Go code. Language kits (ADR 0012) are superseded and will not be built.

## 7. Non-goals

- No `--url` and no scanning of targets that `creep` did not build from local source.
- No server, no telemetry, no "enterprise edition".
- No provider SDKs in the core, and no framework for the CLI.
- No automatic application of fixes.

## 8. Engineering principles

The developer follows these and the auditor checks every PR against them ([ADR 0005](adr/0005-auditor-architecture-review.md)). The principles below are defaults, not rules to force: a deviation from one of them with a stated reason is fine. The layer table (§3), the stable contracts (§4) and the AGENTS.md invariants are not defaults, and no stated reason waives them: a new package adds its own row to the layer table, but loosening an existing row, breaking a contract or changing an invariant needs an ADR first ([ADR 0003](adr/0003-architecture-layers.md)).

- **Patterns** only where they remove real duplication or coupling. Name the problem first; never add a pattern for its own sake.
- **Modularity.** Small packages with one reason to exist (`doc.go` says which). Deep modules: a narrow exported API hiding real work. The layer table in §3 is respected.
- **Testing where it is needed.** New behavior is covered through its edge cases, failure paths and security protections, not trivial happy paths or getters. No test that only restates the implementation. Table-driven; model behavior gets a replay fixture.
- **Scalability and reuse.** Reuse an existing package before adding one. Work per input is bounded: linear time, capped size, and a documented worst case backed by a benchmark. No speculative abstraction.
- **SOLID the Go way, not forced.** Small interfaces declared by the consumer, composition over inheritance, dependencies passed in explicitly: no mutable package-level state used to inject dependencies, no init-time wiring. Read-only package values are fine: sentinel errors (`redact.ErrRunFull`), lookup tables (`refusedPrefixes` in `gateway/addr.go`, the enums in `internal/config`) and constants. Accepted deviation (#133): `internal/gateway` keeps three mutable test hooks, each a no-op `func(string)` in production and called only inside a check-then-open window, between a path's `Lstat` and its open, so a test can swap the path there and prove the open refuses the swap (`O_EXCL` for a new `egress.log`, the same-file or same-directory check otherwise); no other seam reaches inside that window. `testHookBeforeOpen` (`egress.go`) guards the `egress.log` open (`TestOpenRace`), `testHookBeforeDirOpen` (`egress.go`) the run and payload directory opens (`TestDirSwapRefused`, #113), and `testHookBeforeStoreOpen` (`consent_store.go`) the consent store open (`TestStoreSwapRefused`). They stay test-only: they are unexported, so no other package can set them; only `_test.go` files in `internal/gateway` assign them, always restoring the no-op with `t.Cleanup`; and no gateway test calls `t.Parallel`, so tests never race on them. An injected option would put the seam into the exported API (`OpenEgressLog`, `ConsentOptions`), where a caller could run code inside the window.
- **Paradigm mix.** Plain functions and data first; methods on a type when it owns state. Concurrency and parallelism only when they measurably help (I/O fan-out, CPU-bound batches), always bounded and cancellable through `context`.

## 9. Fitness functions

Automated checks that guard an architectural property. A new property needs a check here, not only prose. Atomic checks run on every PR; the per-version review (ADR 0005) is the holistic one.

## 10. Evolutionary architecture

Adapted from *Building Evolutionary Architectures* (Ford, Parsons, Kua), taking only what fits a single-binary CLI with one maintainer.

| Book idea | How creep adapts it | Not adopted |
|---|---|---|
| Fitness functions | The checks in §9, in one table; add one only when a property has no automated guard | No fitness-function framework or dashboard |
| Atomic vs holistic, triggered vs continual | Atomic and triggered: `make check` and CI on every PR. Holistic: the per-version review (whole diff, benchmarks over time) | No production monitoring (no telemetry, invariant 5) |
| Incremental change | Small issues, up to three features in flight in different packages ([ADR 0006](adr/0006-three-features-in-flight.md)), squash merges, sub-issues for L | — |
| Appropriate coupling (connascence) | Layer table and narrow interfaces; the auditor flags strong connascence across a package boundary | No coupling metrics tooling |
| Anticorruption layer | Model contracts translate vendor output into closed schemas before planner or reader see it | — |
| Last responsible moment | ADRs only when a dependency or public contract changes | — |
| Evolvability over predictability | Prefer data (prompts, rules, inventory and tripwire tables, layer table) over code so changes stay local | No speculative plugin systems |

Skipped on purpose: architectural quanta per service, cross-service schema evolution and per-team deployment pipelines. They target distributed systems; creep is one binary with no server.
