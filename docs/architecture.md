# Architecture

This is the source of truth for what each part of `creep` does, which way dependencies may point, and which contracts are stable. Decisions that change it go through an ADR ([index](#adr-index)). The package-by-package list is generated in [map.md](map.md) (`make map`), and the trust boundaries, attackers and mitigations are in [threat-model.md](threat-model.md).

## 1. Context

```
            ┌──────────────┐  local repo (untrusted content)
 developer ─┤              │◄──────────────────────────────
 or CI      │  creep (one  │
 (flags,    │  Go binary)  │──HTTPS──► model endpoints (allowlisted, consented)
  config,   │              │──CLI────► docker/podman, local socket only (v0.2)
  policy)   └──────┬───────┘
                   ▼
   reports (SARIF/JSON/MD) · run state (JSONL) · egress.log · payloads/
```

- The scanned repository is **untrusted input**. Its text can only reach the reader and the redacted gateway payload. It can never reach the planner, a shell or config that loosens a gate.
- The only network peers are configured model endpoints. There is no telemetry or update check by default.
- There is no server and no database. Each run is independent; state is files.

## 2. Pipeline

| Step | Component | Input | Output | Version |
|---|---|---|---|---|
| 1 | calibrate | model contract, seeded language-neutral pseudocode templates (ADR 0037) | per-class scores, tier S/M/L | v0.1 |
| 2 | discover | repo files (whole, redacted, to the model) | entry points, sinks and auth as **IDs, enums and line spans** | v0.2 (static analysis in v0.1) |
| 3 | planner | IDs, enums, booleans and bounded numbers; calibration tier | prioritized hypotheses | v0.1 |
| 4 | reader | redacted slices + hypothesis + recipe hint (installed, checksum-verified and fixture-checked, ADR 0028) | closed-schema verdicts | v0.1 |
| 5 | sandbox + verify | app build (offline, or the operator's mirror on rootless Podman, ADR 0029), PoC template (nightly scans only, ADR 0021) | verified (with a rate) / stays probable | v0.2 |
| 6 | fix | verified finding | suggested diff | v3 |
| 7 | report | run state | SARIF, JSON, Markdown (HTML v1.0) | v0.1 |

Two other drivers reuse these steps (v0.3): `creep mcp` runs a pr-mode scan of the changed files an agent names, with calibration only from the cache (steps 1 cached, 2, 3, 4 and 7; ADR 0027), and `creep bench` runs steps 2 to 4 on the embedded corpus at each forced tier (ADR 0030).

Every model call in steps 1, 2 and 4 goes through the gateway, in this order: `redact.File` → fragment → consent → allowlisted dialer → `egress.log` write-ahead → send. Repository text reaches a payload only from the producers listed on `gateway.Call`: `gateway.FileScan` fragments, `reader.Slicer` slices and `discover` batches of whole files; each cuts only `redact.File` output of the whole file. The planner (step 3) is deterministic and makes no model call; a future model-assisted planner would go through the gateway the same way and need prompts in `internal/planner/prompts/` with a token-budget test.

**Step 2 is language-agnostic** ([ADR 0017](adr/0017-language-agnostic-analysis.md), #265). It is an **inventory** of languages, manifests and container files by file name and bytes; a **lexical tripwire** that matches one cross-language table of sink signatures on the redacted bytes; and **model discovery** (`internal/discover`), where the model reads whole redacted source files through the gateway (the same order as above), a few per call with one synthetic canary file, and proposes entry points, sinks and auth as line spans and enums. creep validates each proposal and assigns the IDs. Tripwire hits and proposals are combined by union only, and every candidate gets the worst-case planner flags (input-dependent, not parameterized, not indirect, on a route not authenticated that takes every method). A batch whose reply misses the canary is not believed: its files are `parse_failed` and the run is incomplete. v0.1's `internal/static` (tree-sitter in wazero, Flask, FastAPI and Express) is removed; its language-neutral rules are in `internal/repofile`.

## 3. Components and layers

A package may import only packages in **lower** layers and only those listed in its row. `make budget` enforces this table (#119), so this block is data and must stay parseable.

```layers

0        internal/gitindex/gitindextest -

1        internal/config         exitcode presets
1        internal/redact         -
1        internal/gitindex       gitindex/gitindextest
1        internal/repofile       -
2        internal/gateway        config redact exitcode
2        internal/gateway/gatewaytest -
3        internal/models         gateway config
3        internal/state          config
```

## 4. Stable contracts

These follow semver once v1.0 ships. Before then, any change needs a note in the PR and, if the change breaks a contract, an ADR.

One exception is settled so later PRs need not decide it: narrowing what the project file (the scanned repository's `creep.yaml`, the untrusted layer) may set or raise is a security fix, not a contract break. ## 5. Extension points

Contributors add **data**, not core code:

- **Presets** (`internal/presets/*.yaml`, embedded in the binary): command lines for model CLIs, selected with `model: { preset: <name> }`. They are community-owned because they track third-party flags; propose one with the *Model preset* issue form and the manual canary check in [CONTRIBUTING.md](../CONTRIBUTING.md#model-presets).
- **Recipes** (v0.3, [ADR 0025](adr/0025-recipes.md)): a JSON file per class with source and sink signatures, a hint for the reader, an optional PoC template and a vulnerable and a safe fixture; written with `creep recipe new`, checked with `creep recipe lint` and loaded with `creep recipe test`, which refuses it unless the model gets both fixtures right. `creep recipe add github.com/<owner>/<repo>@<commit> <clone>` installs a source's recipes from the operator's own clone at a full commit SHA, pinned with checksums in `~/.creep/recipes/creep.lock`; creep makes no network call for it. `scan` loads them only after every checksum matches, the org policy's `recipe_sources` allows each source and each recipe's fixtures pass at the calibrated tier; any fault exits 2 before discovery ([ADR 0028](adr/0028-recipe-install-and-lock.md)). The scanned repository never supplies one.
- **Inventory and tripwire tables** ([ADR 0017](adr/0017-language-agnostic-analysis.md), #265): a file-name or extension row in `internal/discover/inventory.txt`, or a sink signature with its fixture line in `internal/discover/tripwire.tsv`. Both are embedded data with limits checked by tests (`TestTripwireRowsMatchFixtures`, `TestParseInventoryRejects`); no language needs Go code. Language kits (ADR 0012) are superseded and will not be built.

## 7. Non-goals

- No `--url` and no scanning of targets that `creep` did not build from local source.
- No server, no telemetry, no "enterprise edition".
- No provider SDKs in the core, and no framework for the CLI.
- No automatic application of fixes.

## 8. Engineering principles

The developer follows these and the auditor checks every PR against them ([ADR 0005](adr/0005-auditor-architecture-review.md)). The principles below are defaults, not rules to force: a deviation from one of them with a stated reason is fine. The layer table (§3), the stable contracts (§4) and the AGENTS.md invariants are not defaults, and no stated reason waives them: a new package adds its own row to the layer table, but loosening an existing row, breaking a contract or changing an invariant needs an ADR first ([ADR 0003](adr/0003-architecture-layers.md)).

- **Patterns** only where they remove real duplication or coupling. Name the problem first; never add a pattern for its own sake.
- **Modularity.** Small packages with one reason to exist (`doc.go` says which). Deep modules: a narrow exported API hiding real work. The layer table in §3 is respected. Coupling across a package boundary stays weak: the auditor flags strong connascence there (of meaning, position, algorithm, timing or identity) and asks for a named type or a single owner instead; it is a judgment call, so it is a principle, not a §9 fitness function. Accepted deviation (v0.3 review A8): the build-mirror rules (bridge name pattern, reserved bridge names, proxy pattern) exist twice, in `internal/config/validate.go` and `internal/sandbox/mirror.go`, because `config` (layer 1) and `sandbox` (layer 5) may not import each other's owner without loosening a layer row, and both must refuse a bad value on their own (config when a layer loads, sandbox before any build line); `cli/mirror_test.go:TestMirrorRulesMatchConfig` keeps them in step.
- **Testing where it is needed.** New behavior is covered through its edge cases, failure paths and security protections, not trivial happy paths or getters. No test that only restates the implementation. Table-driven; model behavior gets a replay fixture.
- **Scalability and reuse.** Reuse an existing package before adding one. Work per input is bounded: linear time, capped size, and a documented worst case backed by a benchmark. No speculative abstraction.
- **SOLID the Go way, not forced.** Small interfaces declared by the consumer, composition over inheritance, dependencies passed in explicitly: no mutable package-level state used to inject dependencies, no init-time wiring. Read-only package values are fine: sentinel errors (`redact.ErrRunFull`), lookup tables (`refusedPrefixes` in `gateway/addr.go`, the enums in `internal/config`) and constants. Accepted deviation (#133): `internal/gateway` keeps three mutable test hooks, each a no-op `func(string)` in production and called only inside a check-then-open window, between a path's `Lstat` and its open, so a test can swap the path there and prove the open refuses the swap (`O_EXCL` for a new `egress.log`, the same-file or same-directory check otherwise); no other seam reaches inside that window. `testHookBeforeOpen` (`egress.go`) guards the `egress.log` open (`TestOpenRace`), `testHookBeforeDirOpen` (`egress.go`) the run and payload directory opens (`TestDirSwapRefused`, #113), and `testHookBeforeStoreOpen` (`consent_store.go`) the consent store open (`TestStoreSwapRefused`). They stay test-only: they are unexported, so no other package can set them; only `_test.go` files in `internal/gateway` assign them, always restoring the no-op with `t.Cleanup`; and no gateway test calls `t.Parallel`, so tests never race on them. An injected option would put the seam into the exported API (`OpenEgressLog`, `ConsentOptions`), where a caller could run code inside the window.
- **Paradigm mix.** Plain functions and data first; methods on a type when it owns state. Concurrency and parallelism only when they measurably help (I/O fan-out, CPU-bound batches), always bounded and cancellable through `context`.

## 9. Fitness functions

Checks that guard an architectural property. A new property needs a row here, not only prose. A fitness function is objective: it passes or fails on evidence, not on taste; a judgment call is a principle and lives in §8. Most rows are automated; the manual ones are rows too: the per-PR auditor review and the per-version architecture review ([ADR 0005](adr/0005-auditor-architecture-review.md)) and the release pentest ([ADR 0004](adr/0004-pentester-per-release.md)). Every check is static or test-time, never a runtime or production signal, because creep sends no telemetry (invariant 5).

Each row states its **Scope**: atomic (one property) or holistic (several properties in one check); its **Cadence**: triggered (by a PR, a push, a tag or the maintainer) or temporal (on a schedule), and never continual, for the same reason; and its **Invocation**: automated or manual. ## 10. Evolutionary architecture

Adapted from *Building Evolutionary Architectures*, 2nd edition (Ford, Parsons, Kua, Sadalage), taking only what fits a single-binary CLI with one maintainer.

| Book idea | How creep adapts it | Not adopted |
|---|---|---|
| Fitness functions | The checks in §9, in one table, automated or manual; add one only when a property has no guard, and keep each objective (a judgment call is a §8 principle) | No fitness-function framework or dashboard |
| Scope, cadence and invocation | Every §9 row says atomic or holistic, triggered or temporal, automated or manual. Triggered: `make check` and CI on every PR and push, the release pentest and per-version review at the tag. Temporal: weekly CodeQL, Scorecard, govulncheck and fuzzing (#137). Holistic: the `--replay` run over invariants 2, 3 and 5 (#17), the auditor review, the release pentest and the per-version review | Continual checks and production monitoring (no telemetry, invariant 5) |
| Emergent fitness functions | A recurring review lesson becomes a §9 row or a `make budget` check, or the audit says why it cannot be objective; the per-version review asks which findings could become automated checks (§9) | — |
| Incremental change | Small issues, up to three features in flight in different packages ([ADR 0006](adr/0006-three-features-in-flight.md)), squash merges, sub-issues for L | — |
| Appropriate coupling (connascence) | Layer table and narrow interfaces (§3, enforced by `make budget`); connascence is a §8 principle the auditor reviews, not a fitness function | No coupling metrics tooling |
| Anticorruption layer | Model contracts translate vendor output into closed schemas before planner or reader see it | — |
| Last responsible moment | ADRs only when a dependency or public contract changes; each names the §9 row that guards it ([template](adr/0000-template.md)) | — |
| Evolvability over predictability | Prefer data (prompts, rules, inventory and tripwire tables, layer table) over code so changes stay local | No speculative plugin systems |

Not adopted, one line each:

- Continual and production-monitoring fitness functions: no telemetry (invariant 5).
- Architectural quanta, service mesh, data mesh: one binary, no services.
- Database migrations and evolutionary data patterns: no database; JSONL state carries a `v` per line.
- Feature toggles, canary and blue-green releases: no deployment; users pick a version.
- Enterprise governance and Conway's law: one maintainer.
- Postel's law: model output is untrusted and parsed into closed schemas; creep is strict, not liberal, in what it accepts.
- Fidelity fitness functions: no legacy system to replace.
- AI or anomaly-detection fitness functions: nondeterministic, so not objective.
- Coupling metrics (afferent and efferent coupling, instability): noise at about 15 packages; the layer table (#119) governs.
- Sacrificial architecture: conflicts with the stable contracts of §4.
- A mechanical license-drift check in `make budget`: two direct dependencies, and `internal/tools/budget` must not grow (§6); the manual license row in §9 replaces it.
- Version-bump enforcement on golden changes: before v1.0, §4 allows a change with a PR note; revisit at v1.0.
